# 简记 1.3.0 验证报告

## 变更与升级

- 应用标识 `cn.jianji.app`，versionCode 4，最低 API 26，目标 API 35。
- 沿用原签名密钥，APK 支持覆盖升级；文件 SHA-256 见 `SHA256-1.3.0.txt`。
- 数据库版本 4，追加订阅来源与账期列、订阅设置与进度表，保留账目、预算和余额。
- 移除居家入口，旧居家记录改归其他支出。旧备份导入时也做相同归类。
- 购物新增 8 项常用细分；每个支出一级分类均新增每月订阅服务。

## 自动记账设计

- 固定的订阅 ID 与月份派生出唯一扣费记录 ID；写入记录和推进账期在同一事务中完成。
- 已经处理的月份不会因重试或删除历史扣费而重新生成；计划删除后保留停止状态，避免合并旧备份时恢复为活动订阅。
- 金额和扣费日修改保留已处理进度，影响尚未记账的月份。
- 使用本机日期和时区；每月 29～31 日按当月实际天数截断，后续月份保留原扣费日。
- 通过非精确 AlarmManager 闹钟在后台执行，监听重启、应用更新、日期及时区变化以恢复调度；打开 App 时同样补记。每批最多 1,000 笔。
- 新增普通权限 `RECEIVE_BOOT_COMPLETED`。未新增联网权限或精确闹钟权限。

## 已执行的检查

- 原有 114 项纯 Java 收支、余额、筛选和 CSV 检查通过。
- 新增 2,488 项订阅与日期检查通过；其中 2,412 项覆盖 1900～2100 年每个月的月末日期，其余覆盖日期边界、短月、幂等标识、进度、删除状态、订阅来源筛选和购物分类。
- 15 项桌面 SQLite 检查通过：新库与升级库一致、版本 1～3 数据保留、居家迁移后金额和余额不变、扣费唯一性、删除计划保留历史、删除扣费保留进度、停止状态在合并导入时保留，以及账目与进度事务回滚。
- Android 应用及自动检查代码编译；APK v2/v3 签名、ZIP 对齐检查通过。
- 自动检查源码补充了真实 Android 数据库上的月末扣费、补记、重试、修改、删除、备份恢复和界面选项检查，已编译，未执行。

## 验证范围

当前未连接可用 Android 测试设备，先前本机模拟器未能启动。本版尚未完成 Android 设备上的覆盖升级、界面操作、后台闹钟、重启恢复及视觉检查。桌面 SQLite 和纯 Java 检查不能替代设备验证。

后台任务受 Android 系统及厂商省电策略影响，可能延后；打开 App 会重新安排并补记到期账期。[Android 官方闹钟文档](https://developer.android.com/develop/background-work/services/alarms)

JSON 备份格式为版本 4，包含订阅设置、账期进度、停止状态及记录来源，兼容版本 1～3。已有订阅在合并导入时保留本机设置与进度。
